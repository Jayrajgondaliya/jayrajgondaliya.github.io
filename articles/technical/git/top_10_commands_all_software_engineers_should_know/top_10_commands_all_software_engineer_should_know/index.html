10 Git Commands All Software engineers Should Know

February 6, 2026

1. Interactive staging: Stage Only What You Want#

Starting with one of my favorite

Imagine, You’re working on a bug in app.py. To debug, you sprinkled temporary print statements all over the code. You finally fix the bug, and now you want to commit your changes.

But there’s a problem: if you do:

git add app.py
git commit -m "Fix bug in login function"

Git will stage everything, including your debug prints. You don’t want those cluttering the commit.

Normally, you’d have to manually remove all the debug lines, commit, and then re-add them if needed. Painful.

Welcome to the interactive staging:

git add -p app.py

Git now shows your changes in small “hunks” and asks what to do with each one:

y — stage this hunk (the bug fix)
n — skip this hunk (the debug prints)
s — split the hunk into smaller pieces
q — quit staging

Suddenly, you can stage only the bug fix, leaving all debug lines in your working directory. When you commit, your history is clean, and your debug prints stay intact for further testing.

Tip: Interactive staging is a lifesaver when working on multiple tasks in the same file. It keeps your commits focused, clean, and review-friendly.

1. Reset to a specific date/time#

Question: Can I reset my repository to how it looked at a specific point in time?#

Answer: Yes! You can use git reflog combined with git reset.

Example: Reset your repo to the state it was at 2 PM on Jan 22, 2026:

git log –before=“2026-01-22 14:00” git reset –hard

Tip: This is incredibly useful if you made multiple bad commits and want to go back in time.

Image idea: Timeline showing commits and moving HEAD back to a specific timestamp.

2. Undo multiple commits without losing changes#

Question: I want to undo my last 3 commits but keep the changes in my working directory.

Answer:

git reset –soft HEAD~3

–soft keeps changes staged.

–mixed keeps changes unstaged.

Use case: You committed too early and want to fix messages or combine commits.

3. Amend the last commit#

Question: Can I fix the last commit without creating a new one?

Answer:

git commit –amend -m “Corrected commit message”

You can also add new files to the last commit:

git add forgotten_file.txt git commit –amend –no-edit

4. Squash multiple commits into one#

Question: How do I clean up my commit history before pushing?

Answer: Interactive rebase is your friend:

git rebase -i HEAD~5

Mark commits as squash or fixup to combine them.

Tip: Perfect for cleaning messy feature branches.

5. Recover deleted branches#

Question: Oops, I deleted a branch. Can I get it back?

Answer:

git reflog git checkout -b

Tip: Reflog tracks all changes, even on deleted branches.

6. See who changed a specific line#

Question: How do I find who last modified a line in a file?

Answer:

git blame

Use -L , to focus on specific lines.

Use case: Debugging or understanding code history quickly.

7. Stash specific files#

Question: I want to stash only some files, not everything.

Answer:

git stash push -m “WIP for login” path/to/file1 path/to/file2

Tip: Useful when working on multiple tasks simultaneously.

8. Cherry-pick a commit#

Question: Can I apply a single commit from another branch?

Answer:

git cherry-pick

Use case: Useful when hotfixes are needed without merging the entire branch.

9. Clean untracked files safely#

Question: How do I remove all untracked files but keep the repo safe?

Answer:

git clean -n # dry run git clean -f # actually delete git clean -fd # include directories

Tip: Use -n first to preview what will be removed.

💡 Pro tip for your favorite: Resetting to a specific time can also be automated:#

TARGET_DATE=“2026-01-22 14:00” COMMIT=$(git rev-list -1 –before="$TARGET_DATE" main) git reset –hard $COMMIT
